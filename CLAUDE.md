Бот для **Subway Surfers City** (лише City, класичний Subway Surfers не
підтримується) на Android-телефоні без root, який підключено до ноутбука
(Fedora, Wayland) через USB. Навчальний проєкт для університету.

## Команди

```bash
.venv/bin/python -m unittest discover tests          # тести (без телефону)
.venv/bin/python tools/doctor.py                     # перевірка adb/телефону/захоплення
.venv/bin/python main.py --dry-run --show            # бот без свайпів, з вікном налагодження
.venv/bin/python main.py --backend image --image <dir> --dry-run   # офлайн на записаних кадрах
.venv/bin/python main.py --tour                      # картка рівня відкрита → упізнати, PLAY, маршрут
.venv/bin/python tools/build_routes.py --channel https://www.youtube.com/@zero_mode_yt --model models/player.pt
```

`build_routes.py` кешує аналіз кожного відео в `rec/videos/*.analysis.npz`;
після зміни алгоритмів маршрути перебудовуються за секунди. Кеш містить
рамки персонажа, тож після перетренування `models/player.pt` його треба
видалити.

Тур переробили ~13.06.2026, відео Zero Mode старші. Новіші проходження
горизонтальні: там PLAY тиснуть на головному екрані без картки рівня, тому
завдання беруться з екрана результатів після забігу (`video.tiles_text`,
кадр 1080p докачується по секунді в `rec/videos/hires/`). yt-dlp без deno
YouTube обмежує до ~13 КБ/с: deno стоїть у `.venv` (`pip install deno`),
запускати з `PATH=$PWD/.venv/bin:$PATH`. Нові маршрути спершу в
`routes_new/` (не в git), після перевірки — у `routes/`.

Залежності: `.venv/bin/pip install -r requirements.txt` (torch для CPU:
`--index-url https://download.pytorch.org/whl/cpu`). Системно потрібен
лише `adb` (`android-tools`).

## Архітектура

Конвеєр: `capture` → детектор → `scene` → `brain` → `controls`.

- `bot/capture.py` — джерела кадрів: `screenrecord` (за замовчуванням,
  H.264 через PyAV), `v4l2` (scrcpy), `screencap`, `image`. Потокові
  бекенди тримають лише останній кадр.
- `bot/detector.py` (YOLO, ultralytics) і `bot/heuristic.py` (HSV, OpenCV)
  мають однаковий інтерфейс `detect(frame) -> list[Detection]`. Евристика
  потрібна для авторозмітки датасету й як запасний режим.
- `bot/classes.py` — список класів. **Порядок = індекси YOLO**: нові класи
  додавати лише в кінець, інакше зламаються натреновані моделі й датасети.
- `bot/geometry.py` — перспективні смуги (точка сходу), усі координати
  нормовані 0..1. **Камера йде за гравцем вбік**: смуги екранні
  (ліва / поточна / права), абсолютну смугу пам'ятає `Brain`.
- `bot/scene.py` — розкладає детекції по 3 смугах і зонах near/far/pickup.
  Глибина перешкоди = низ рамки.
- `bot/brain.py` — правила за пріоритетом: вижити → заздалегідь змінити
  смугу → ховерборд → stomp → стрибок до дрона/бабла → предмети. Бот ніколи не йде в смугу з
  перешкодою заради предметів.
- `bot/controls.py` — `input swipe/tap` через один постійний `adb shell`.
- `bot/route.py` — маршрути City Tour: запис з `getevent`, стрибки й
  пірнання з траєкторії персонажа (`actions_from_track`), відтворення
  (`RoutePlayer`). Режим старту: `tap` (свій запис, з тапу «Грати»), `hud`
  (з відео: t=0 — поява HUD забігу, бот синхронізується сам), `manual`.
- `bot/video.py` — аналіз відео без нейромережі: кнопка паузи HUD (межі
  забігів, синхронізація), зміни смуги за зсувом рейок (`lane_events` з DP,
  що відкидає неможливі переходи), кнопка PLAY і відбиток блоку завдань
  на картці рівня.
- `bot/library.py` — бібліотека маршрутів; рівень упізнається за текстом
  завдань на картці (RapidOCR, `video.card_text`), бо порядок рівнів у турі
  перемішаний. Порівняння (`video.text_similarity`) — переважно за набором
  чисел завдань, стійке до помилок OCR і порядку рядків. Спроба рівня
  обирається за станом картки (`card_state`: які завдання вже зелені).
- `routes/` — 276 маршрутів-спроб з каналу Zero Mode (+ `cards/`, `crew/`
  вирізки JPEG). `tools/check_routes.py` — автоматична перевірка.
- `models/player.pt` — детектор лише класу `player`, натренований на
  кадрах з відео каналу Zero Mode (розмітка вручну). Потрібен для
  `build_routes.py`; повної моделі для звичайного режиму поки немає.
- `config.json` — усі пороги й таймінги; `profiles` перевизначають
  `lanes`/`zones`/`heuristic` під райони.

## Правила

- Root на телефоні недоступний: не використовувати `sendevent`, запис у
  `/dev/input` та інше, що його потребує. Цільовий телефон — POCO X6 Pro
  (HyperOS); для `input` там потрібен перемикач «Налагодження USB
  (налаштування безпеки)».
- Коментарі, докстрінги, повідомлення CLI й README — українською.
  Повідомлення комітів — англійською.
- Комітити кожну нову фічу окремим комітом.
- Зміни в логіці супроводжувати тестами в `tests/test_bot.py` (синтетичні
  кадри й детекції, без телефону).
- Не комітити кадри гри, датасети, ваги моделей (`rec/`, `dataset/`,
  `runs/`, `*.pt`) — це вже в `.gitignore`. Маршрути `routes/*.json`
  комітити можна й треба.
- Не вигадувати маршрути рівнів чи кольори об'єктів гри: маршрути беруться
  лише із записів або відео, кольори — з піпетки `tools/calibrate.py`.
- Звичайний режим (`brain`/евристика) без запиту користувача не змінювати;
  поточний пріоритет — маршрути туру.
- Відомі обмеження маршрутів з відео: stomp вмикається лише консервативно
  (більшість stomp-завдань не виконується); таймінг перевірено лише на
  відео, не на телефоні; check_routes показує ~21 відео, де кількість
  рівнів не збігається з назвою (групування спроб за шумним OCR з відео).
