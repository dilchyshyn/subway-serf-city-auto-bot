# Subway Surfers City Bot

Бот, який грає в **Subway Surfers City** на Android-телефоні, підключеному
до ноутбука кабелем. **Root не потрібен**, хостинг теж: усе працює на
ноутбуці.

- **Звичайний забіг.** Нейромережа YOLO знаходить на кадрі перешкоди,
  монети, бусти й персонажа, а правила вирішують, що робити: вижити →
  увімкнути ховерборд → stomp → збирати предмети.
- **Рівні City Tour.** Рівні не змінюються, тому бот повторює записаний
  маршрут, у якому виконано всі 3 завдання. Маршрут можна записати зі
  свого проходу або відновити з відео чужого проходження.

```
телефон ──adb screenrecord──▶ capture ──▶ YOLO ──▶ scene (3 смуги) ──▶ brain ──▶ adb swipe/tap ──▶ телефон
                                                                      ▲
                                             routes/<рівень>.json ────┘  (режим City Tour)
```

## Що бот уміє «з коробки», а що треба зробити один раз

| | З коробки | Що зробити один раз |
|---|---|---|
| Звичайний забіг | правила гри (`bot/brain.py`) | **навчити модель**: записати й розмітити ~300–500 кадрів, тренування ~15 хв у Colab або 1–2 год на CPU |
| Рівень City Tour | вміє відтворювати маршрути | **отримати маршрут рівня**: пройти рівень під записом **або** конвертувати відео 3-зіркового проходження |

Бот не вчиться сам під час гри. Навчання з підкріпленням на реальному
телефоні вимагало б тисяч годин гри в реальному часі, тому тут
використовується навчання з учителем: ти показуєш (розмітка, маршрути),
бот повторює.

Готових маршрутів для всіх рівнів ніде немає: їх треба записати. Але
кожен рівень записується **один раз**, а файли `routes/*.json` можна
викласти на GitHub і ділитися ними з одногрупниками.

## Як це працює

1. **Захоплення** (`bot/capture.py`): `adb exec-out screenrecord` віддає
   H.264-потік, PyAV його декодує. Запасні варіанти: scrcpy + v4l2loopback
   або `screencap`.
2. **Зір**: `bot/detector.py` (YOLO) або `bot/heuristic.py` (кольорові
   евристики OpenCV, потрібні для авторозмітки). Обидва повертають
   однаковий список детекцій. Класи описано в `bot/classes.py`:

   | Клас | Що це | Що робить бот |
   |---|---|---|
   | `obstacle_tall` | вагон, контейнер, навантажувач | обходить |
   | `obstacle_low` | низька перешкода | стрибає |
   | `obstacle_high` | планка зверху | пірнає |
   | `coin` | звичайна монета | збирає (вага 2) |
   | `board_coin` | монета для бордів | збирає, якщо немає звичайних (вага 1) |
   | `energy` | синя Board Energy | збирає (вага 4) |
   | `powerup` | Magnet, Bubblegum, Batteries, Coin doubler, Board charge | пріоритет (вага 10) |
   | `star` | Secret Star | найвищий пріоритет (вага 15) |
   | `stomp_target` | об'єкт, з якого stomp вибиває монети | іде в його смугу, стрибає й б'є вниз |
   | `board_ready` | повна шкала ховерборда (HUD) | тапає, щоб увімкнути ховерборд |
   | `player` | персонаж | не перешкода; клас зарезервовано під маршрути з відео |

3. **Сцена** (`bot/geometry.py`, `bot/scene.py`). Камера в City йде за
   персонажем вбік, тому на екрані по центру завжди поточна смуга, а
   ліворуч і праворуч — сусідні. Абсолютну смугу бот пам'ятає сам, щоб не
   свайпати в стіну. Детекції розкладаються по смугах і зонах `near` (реагувати
   зараз), `far` (заздалегідь) і `pickup` (де збирати).
4. **Рішення** (`bot/brain.py`), за пріоритетом:
   1. Перешкода попереду → у вільну сусідню смугу, а серед вільних туди,
      де більше предметів. Якщо обидві зайняті, стрибнути або пірнути.
   2. Перешкода далі → заздалегідь піти в повністю чисту сусідню смугу.
   3. Ховерборд готовий → тап (він ще й друге життя).
   4. Stomp-ціль просто попереду → стрибок і свайп вниз.
   5. Шлях вільний → перейти в чисту сусідню смугу, якщо там предметів
      цінніше хоча б на `pickup_min_gain`. У смугу з перешкодою бот заради
      предметів не йде ніколи.
5. **Керування** (`bot/controls.py`): `input swipe` / `input tap` через
   один постійний `adb shell`.
6. **Маршрути** (`bot/route.py`): запис дотиків через `getevent`,
   відновлення дій з відео, відтворення з таймінгом.

## Підготовка

### Телефон (приклад для POCO X6 Pro / HyperOS)

1. Налаштування → Про телефон → **7 разів тапни «Версія ОС»**.
2. Додаткові налаштування → Для розробників:
   - **Налагодження USB**: увімкнути;
   - **Налагодження USB (налаштування безпеки)**: увімкнути. Без нього
     HyperOS блокує свайпи від adb. Перемикач вимагає увійти в Mi-акаунт,
     вставлену SIM-картку та інтернет.
3. Підключи кабель, обери «Передача файлів» і підтвердь запит на телефоні.

На інших телефонах достатньо пункту 1 і «Налагодження USB».

### Ноутбук (Fedora)

```bash
sudo dnf install android-tools
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python tools/doctor.py     # перевіряє все й підказує, що виправити
```

### Калібрування смуг (один раз під свій екран)

```bash
.venv/bin/python tools/calibrate.py
```

Повзунками підгони трапеції під дорогу так, щоб зона `near` була трохи
попереду персонажа. Збереження клавішею `s`.

## Навчання моделі

```bash
# 1. Набери кадри: грай сам, бот лише записує (кожен 5-й кадр)
.venv/bin/python main.py --vision heuristic --dry-run --record rec/docks
#    і/або кадри з відео проходжень (yt-dlp: .venv/bin/pip install yt-dlp)
.venv/bin/python tools/extract_frames.py "https://youtube.com/watch?v=..." rec/yt1 --fps 2

# 2. Датасет з чорновими мітками (монети, Energy, пауер-апи, перешкоди)
.venv/bin/python tools/autolabel.py rec/* --zip
```

3. **Виправ розмітку** в редакторі, який розуміє формат YOLO:
   [Roboflow](https://roboflow.com) (завантаж `dataset.zip`, виправ,
   експортуй «YOLOv8») або локальний
   [X-AnyLabeling](https://github.com/CVHub520/X-AnyLabeling). Додай
   рамки, яких евристика не знаходить: `player`, `board_coin`,
   `stomp_target`, `star`, `board_ready`, і виправ тип перешкод
   (`low`/`high`). Достатньо ~300–500 кадрів з усіх районів.

4. **Тренування**:
   ```bash
   .venv/bin/python tools/train.py                    # на CPU ноутбука, 1–2 год
   .venv/bin/python tools/train.py --export openvino  # + швидша модель для CPU
   ```
   Або в **Google Colab** (безкоштовний GPU, ~15 хв): завантаж
   `dataset.zip` і виконай:
   ```
   !pip install ultralytics
   !unzip -q dataset.zip -d dataset
   !yolo detect train data=dataset/data.yaml model=yolo11n.pt epochs=80 imgsz=640
   ```
   Скачай `runs/detect/train/weights/best.pt` і поклади як `models/city.pt`.

## Гра

```bash
.venv/bin/python main.py --dry-run --show   # спершу подивись рішення без свайпів
.venv/bin/python main.py --show             # грати
```

Клавіші у вікні `--show`: `r` — смуга = середня, `p` — пауза, `q` — вихід.
Поки моделі немає, можна грати з `--vision heuristic`, але це помітно
гірше.

## Рівні City Tour

**Варіант 1. Записати свій прохід** (найточніше):

```bash
.venv/bin/python tools/record_route.py docks_07
# відкрий екран рівня → «Грати» → пройди з усіма 3 завданнями → Ctrl+C
.venv/bin/python main.py --route routes/docks_07.json
# бот сам натисне «Грати» й повторить прохід
```

**Варіант 2. З відео чужого проходження** (експериментально, потрібна
модель з класом `player`):

```bash
.venv/bin/python tools/route_from_video.py "https://youtube.com/watch?v=..." docks_07 \
    --start 4.2 --end 71.5 --crop 0.33,0,0.34,1
.venv/bin/python main.py --route routes/docks_07.json
# натисни «Грати», потім Enter у момент, коли персонаж почне бігти
```

`--start`/`--end` — секунди старту й фінішу у відео, `--crop` — де у
відео екран гри (частки кадру x,y,w,h). Тапи (ховерборд) і stomp у
повітрі з відео не відновлюються.

**Якщо маршрут «з'їжджає»:**
- `--route-offset 0.2` зсуває всі жести пізніше (від'ємне значення — раніше);
- `--route-guard` між жестами маршруту стрибає/пірнає перед несподіваною
  перешкодою (смугу не змінює, щоб не зламати маршрут).

## Параметри (`config.json`)

| Параметр | Що означає |
|---|---|
| `capture.backend` | `screenrecord` (за замовчуванням), `v4l2`, `screencap`, `image` |
| `vision` | `yolo`/`heuristic`, шлях до моделі, поріг впевненості, розмір входу |
| `lanes`, `zones` | геометрія смуг і зон (налаштовується в `calibrate.py`) |
| `weights` | цінність предметів для вибору смуги |
| `pickup_min_gain`, `pickup_bias` | наскільки охоче бот змінює смугу заради предметів |
| `action_cooldown`, `stomp_delay`, `stomp_cooldown` | таймінги дій, с |
| `board.tap`, `board.cooldown` | куди тапати для ховерборда й як часто |
| `swipe` | точка старту, довжина й тривалість свайпу |
| `heuristic` | HSV-пороги для авторозмітки; `profiles` перевизначає їх під райони |

## Тести

```bash
.venv/bin/python -m unittest discover tests
```

Тести перевіряють розкладання детекцій по смугах, пріоритети рішень,
евристики на синтетичних кадрах, розбір `getevent`, відновлення дій з
траєкторії персонажа й відтворення маршрутів.

## Обмеження

- **Затримка adb**: `input swipe` запускає на телефоні JVM, і це
  100–300 мс. На великій швидкості бот може не встигати.
- **Маршрути прив'язані до часу.** Якщо телефон завантажує рівень довше,
  ніж під час запису, потрібен `--route-offset`. Маршрути з відео менш
  точні, ніж записані власноруч.
- Бот не перезапускає гру після програшу і не проходить меню сам (окрім
  тапу «Грати» в записаному маршруті).
- Сила гри залежить від якості розмітки: чим більше різноманітних кадрів
  з різних районів, тим краще.

## Етика

Проєкт навчальний. Не використовуй бота в онлайн-рейтингах, турнірах чи
подіях, де ти змагаєшся з іншими гравцями: це порушує правила гри й
нечесно щодо інших. Кадри й відео з гри використовуй лише для
навчання власної моделі й не викладай їх у репозиторій (`.gitignore` це
вже враховує).
